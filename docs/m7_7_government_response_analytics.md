# Module M7.7: Government Response Analytics

## 1. Executive Summary & Epistemic Stance

> **CORE INVARIANT: STRICT EPISTEMIC TRANSPARENCY & NON-MASQUERADING**
> *"All metrics generated by the CVKI Government Response Analytics Engine are internal system-derived performance indicators (`is_system_derived = True`, `is_official_sla = False`). They MUST NEVER masquerade as official government SLAs or statutory guarantees. When sample counts are zero, metrics must explicitly report `None` (null) rather than defaulting to misleading `0.0` values."*

Module M7.7 delivers the **Government Response Analytics Engine** of the CVKI platform. It aggregates, computes, and visualizes cross-departmental response metrics, transition latencies, resolution verification rates, escalation frequencies, data quality indicators, and chronological case lifecycle timelines across all integrated public authorities.

### Key Capabilities & Invariants
1. **Deterministic Summary Aggregations:** Computes total cases, government-linked cases, confirmed reference mappings, active vs. closed cases, and normalized external status distributions.
2. **Epistemically Honest Latency Tracking:** Measures transition latency across key lifecycle milestones:
   - Registration to Under Review
   - Registration to Assigned
   - Registration to In Progress
   - Registration to Resolved
   *(If no cases have reached a milestone, latency and sample count strictly report `None` and `0`, never `0.0` hours).*
3. **Citizen Resolution Verification Analytics:** Aggregates verification rates, dispute rates, unverified resolution counts, and breakdown of physical verification statuses.
4. **Escalation Engine Analytics:** Summarizes follow-up counts, escalation recommendations, cooldown suppression counts, and threshold exceedances.
5. **Department & Authority Breakdown:** Segregates metrics by integration adapter (e.g. `bbmp_sahaaya`, `cpgrams`) to expose comparative responsiveness and data quality.
6. **Data Quality & Health Signals:** Quantifies missing status counts, stale status counts, unknown status counts, and unconfirmed reference mappings.
7. **Chronological Case Lifecycle Timeline:** Synthesizes an end-to-end audit timeline per complaint case, uniting submission events, reference confirmations, status sync observations, escalation policy triggers, and citizen verification actions.

## 3. Schema Definitions (`backend/app/schemas/government_analytics.py`)

### Core Latency & Performance Schemas
```python
class TransitionLatencyMetric(BaseModel):
    transition_name: str
    sample_count: int
    avg_latency_hours: Optional[float] = None
    median_latency_hours: Optional[float] = None
    min_latency_hours: Optional[float] = None
    max_latency_hours: Optional[float] = None
    is_official_sla: bool = False
    is_system_derived: bool = True

class ResolutionVerificationMetrics(BaseModel):
    total_government_resolved_cases: int
    verified_resolved_count: int
    citizen_disputed_count: int
    partially_resolved_count: int
    needs_review_count: int
    unverified_resolved_count: int
    verification_rate: Optional[float] = None
    dispute_rate: Optional[float] = None
    is_system_derived: bool = True

class GovernmentAnalyticsSummaryResponse(BaseModel):
    total_complaint_cases: int
    government_linked_cases: int
    reference_confirmed_cases: int
    active_cases: int
    closed_cases: int
    status_distribution: list[GovernmentStatusDistributionItem]
    transition_latencies: list[TransitionLatencyMetric]
    resolution_verification: ResolutionVerificationMetrics
    escalation_analytics: EscalationAnalyticsMetrics
    authority_performance: list[AuthorityPerformanceAggregate]
    data_quality: DataQualityMetrics
    generated_at: datetime
    is_official_sla: bool = False
    is_system_derived: bool = True
    disclaimer: str = (
        "Metrics are internal system-derived performance indicators based on observed "
        "portal transitions and citizen verifications. They do not constitute official "
        "statutory government SLAs."
    )
```

## 5. Security & Role-Based Access Control (RBAC)

1. **Admin Analytics Access:** All `/api/v1/admin/government/analytics/*` endpoints are protected by `require_roles([UserRole.SUPER_ADMIN, UserRole.CITY_OFFICIAL, UserRole.DEPARTMENT_STAFF])`. Unauthorized citizen requests receive `403 Forbidden`.
2. **Case Timeline Access:** The `/api/v1/government/cases/{ref}/analytics/timeline` endpoint allows case owners (`case.user_id == current_user.user_id`) and authorized staff to view the timeline. Any attempt by an unauthorized citizen to view another citizen's case timeline returns `404 Not Found` (case isolation).
