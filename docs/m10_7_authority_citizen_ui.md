# CVKI Module 10.7: Authority Decision Support & Citizen Clarification UI & APIs

## 1. Overview
Module 10.7 delivers the human-in-the-loop interfaces and dual-perspective API gateways for CVKI's Evidence-Aware Decision Support Engine. It separates authority decision management from public citizen transparency while preserving strict epistemic integrity.

### Core Principles
- **Dual Perspectives**: Specialized interfaces for municipal authorities (detailed operational context, playbook checkpoints, human review controls) and citizens (plain-language explanation, privacy-protected location, active clarification prompts).
- **Location Privacy**: Citizen-facing endpoints blur coordinates by approximately ~100 meters (`fuzz_coordinates`) to prevent citizen doxxing while maintaining community context.
- **Epistemic Invariance**: Citizen clarification answers are strictly tagged as `USER_REPORTED` and never promote automatically to `VERIFIED_EVIDENCE`.
- **Statutory Non-Delegation**: Every interface explicitly displays statutory disclaimers affirming that algorithmic outputs are advisory recommendations, not legally binding government orders.

## 2. API Endpoints
### Citizen Gateway (`/api/v1/decision-support/cases/{reference_id}/...`)
- `GET /citizen-view`: Returns plain-language case status, fuzzed coordinates (~100m radius), evidence status (available vs. needed), and active clarification prompts.
- `GET /clarification`: Fetches active, targeted clarification questions generated by M9.3.
- `POST /clarify`: Submits citizen clarification responses. Input is validated via M9.3 validator, saved as `USER_REPORTED` clarification record, and triggers an updated decision context re-evaluation without mutating the case status.

### Authority Review Gateway (`/api/v1/decision-support/cases/{reference_id}/...`)
- `POST /review`: Records authority officer decisions (`ACCEPTED`, `OVERRIDDEN`, `DISMISSED`) along with mandatory reviewer notes and justification. Anchored immediately into M10.6 provenance and knowledge graph.

## 3. Frontend Component Architecture
### Authority Interfaces
- **`AuthorityDecisionPanel.jsx`**:
  - Displays evidence quality badges (`STRONG`, `PARTIAL`, `CONFLICTING`, etc.) and P1–P4 priority.
  - Lists playbook recommendations clearly labeled "CVKI Recommended Action".
  - Interactive "View Field Inspection Checkpoints" drawer.
  - Human review control section allowing officers to accept or override recommendations.
- **`FieldInspectionPanel.jsx`**:
  - Displays structured physical checkpoints and required PPE.
  - Inspector form to record defect confirmation, measurements, photo uploads, and GPS check.
  - Automated audit report card showing geospatial tolerance and compliance score.

### Citizen Interfaces
- **`CitizenCaseView.jsx`**:
  - Clean, jargon-free summary of reported civic issue.
  - Privacy-fuzzed map coordinates with descriptive landmark guidance.
  - Clear breakdown of evidence currently available and evidence still requested.
  - Embedded disclaimer: "Advisory decision support system. Final actions subject to municipal inspection."
- **`CitizenClarificationCard.jsx`**:
  - Targeted single-question cards for ambiguous or low-confidence cases.
  - Form validation with clear notice: "Your answer will be treated as a reported observation."

## 4. Security & Compliance
- Role-based access control (RBAC): Authority review and raw field coordinates require `authority` or `admin` scopes.
- Citizen clarification answers are sanitized against injection attacks and rate-limited.
